# Changelog

All notable changes to the Super Merged custom work are recorded here.
Third-party components (Gun Bonsai, Hyper-V, VUAS, Indestructible, Doom Points, libtooltipmenu) have their own histories upstream.

## [Unreleased]

### Added
- **Player shots pass through companions (optional).** New `F_PassPlayerShots` CVar (default off), toggle under Companions > Combat Behavior. While a player-fired missile (rocket, plasma) is close enough to reach a companion, that companion is made THRUACTORS for that tic so the missile flies on instead of blocking. Enemy missiles are unaffected.
- **Companion orders: Stay / Follow / Toggle.** New keybinds under "Gun Bonsai - Companions" (`companions-stay`, `companions-follow`, `companions-toggle`, unbound by default). The order is the `companions_stay` CVar (not archived), also shown as "Companions stay put" in Companions > Combat Behavior. While staying, companions do not follow the player or teleport to them (they carry `STANDSTILL`, because the engine's own friendly-follow otherwise still walks them to about 120 units of the player); they still fight enemies in range.

### Known limitations
- **Hitscan shots (pistol, shotgun, chaingun) still hit companions.** `F_PassPlayerShots` only covers missiles. A hitscan pass-through was tried and removed: while the attack button was held, companions in the line of fire were made non-shootable (`bNONSHOOTABLE`) from the companion's own tick. In a live test (UZDoom, empty room, friendly Demon 160 units ahead, Super Shotgun and chaingun, option on) the shots still produced a puff on the Demon. The likely cause is ordering: the player's weapon fires before the companion's tick runs, and a mouse click only holds the attack bit for one tic, so the flag is never set in time. Untested alternative: do the marking from `WorldTick` in the event handler, which probably runs before the actors act, and restore the flag the tic after the line is clear. That was judged not worth the per-tic block-map search and was not built. A side effect of any version of this approach is that enemies cannot hit the marked companion while it is non-shootable.

### Changed
- **Chain Lightning hops vs start cue.** `lightning/arc` is the eight shorter snaps kept from `chain_zap_arc_r0` (`assets/sfx/chain_zap_arc_picked.json`). `lightning/chain` is the six longer `lightning_chain_r0` keeps plus `s9r0g0c013` (`assets/sfx/lightning_chain_picked.json`). Round 1 of the hop search was the same family and is not used. No extra low-pass. Thunderbolt and revive cues are unchanged. Same `bonsai_sfx_lightning` switch and `$limit` 5 on hops.

### Added
- **Save Gate upgrade (bridge to Simple Saving).** A new player upgrade, `TFLV_Upgrade_SaveGate`, lets you keep Simple Saving's quicksave, save item drops and event saves locked until you earn it. 4 levels by default (`bonsai_savegate_max_level`): Lv1 unlock, Lv2 secrets give save items, Lv3 bosses can drop them, Lv4 save items survive map changes; every level also raises how many you can hold (`bonsai_savegate_cap_base` + (level - 1) * `bonsai_savegate_cap_per_level`, default 2 to 5). Off by default. The upgrade is only offered when Simple Saving is loaded and the switch is on; Simple Saving ignores the gate when this class is not loaded, so neither mod can lock the other by accident. The class sits in this pk3 (a ZScript class cannot extend Gun Bonsai from another pk3) and only writes Simple Saving's `nosave_gate_*` CVars through `TFLV_SaveGateHandler` (on map load, spawn and about once a second). Settings are in Gun Bonsai Options > Save Gate and are saved with the balance profiles; starting guesses: Default off, Balanced on (cap 3, 4 levels), Challenging on (cap 2, 4 levels), Punishing on (cap 1, 3 levels), Brutal on (cap 1 and no growth, 3 levels). Pool rarity `bonsai_upg_savegate` defaults to Favored so a locked game is offered it soon. Saving from the Save menu and engine autosaves are never locked. Simple Saving's side (descriptive save names, per-map cap, the gate rules) is in its own repo. Verified in the Live Tester on UZDoom 5.0.3 (Doom II MAP05, scratch scenarios): both pk3s load together and each alone; a locked quicksave does nothing, taking the upgrade unlocks it and Lv2 is reported; all five profiles apply the right gate values; not yet played by hand. New test helper `bonsai_dbg net-event/<name>` sends a network event.
- **Rare artifact: one free upgrade choice.** A rare gold pickup that gives your equipped weapon one free upgrade choice (the normal upgrade menu; the weapon's level, XP and bonus levels do not change, and the respec and Legendoom checks of an ordinary level-up do not run). It can appear beside a Megasphere, Soulsphere, Invulnerability sphere, Blue armour or Berserk/Partial Invisibility/Radiation Suit (each kind has its own chance, default 0.5-1.5 %), and drop from `+BOSS` monsters (default 10 %). Chances are rolled once when the item appears, never when you touch it, with a master switch, a boss-drop switch and a per-map limit (default 1). Chances are percent values with 0.1 steps. All in Gun Bonsai Options > Rare finds (`bonsai_artifact_*`), and saved and applied with the balance profiles. The artifact is a generated gold gem sprite (`assets/sprites/artifact.json`, Doom Creator Toolkit). If the artifact cannot be used (no weapon, an ignored weapon, no upgrade available) it stays on the floor; declining the choice drops it again. Vanilla item classes only: items that another mod replaces with unrelated classes are not detected.
- **Fixed: Elemental Synthesis crashed with Blood.** A weapon with Blood plus another element and an Elemental Beam, Blast or Wave aborted the script on the first hit (Blood was read from tables that only cover Fire, Acid, Poison and Lightning). Blood is now skipped, since it has no effect to copy, and a weapon with a single element no longer reads past its colour list.

Nothing plays when there was nothing to copy. Own switch `bonsai_sfx_synthesis` (Full tier), at most every 40 tics.

It is on the Lightning sound switch (`bonsai_sfx_lightning`) at the Full tier; when off, or on the Essential tier, the old vanilla sound plays, so a hop is never silent. At most 5 overlap.
- **Original small-explosion sound (provisional).** Explosive Shots and Submunitions bomblet blasts now play an original short, soft, low boom (7 random variants picked by ear, at most 6 nearby at once, distance-based: full volume close, fading to silence by about 1200 units with a very faint far cue to about 6000) instead of the borrowed vanilla fireball sound (`bonsai/smallboom`). New switch `bonsai_sfx_explosion` (Essential tier): turning it off switches back to the old vanilla sound rather than silencing the blast. Sounds: `assets/sfx/explosions_picked.json` (made with the Doom Creator Toolkit sound-search lab, rounds 4-5; CC0; the older `gen_explosions.py` candidates are no longer shipped). Verified: compiles, lookups in the Live Tester (`rpg_sfx_explosion`); not yet heard in a real fight.
- **Blood and Infernal Kiln sound cues (provisional sounds).** Exsanguinate heal burst on a kill (`blood/exsanguinate`, from the dead enemy, within 700 units), Vital Drain armour gain (`blood/vitaldrain`, from the player, at most every 40 tics, only when armour was actually added) and Infernal Kiln lighting up (`fire/kiln`, from the player, on the edge from no buff to some, at most every 40 tics; controlled by the Fire switch). New switch `bonsai_sfx_blood` (Full tier). The per-element cue gate is now an array of six windows (fire, lightning, acid, poison, blood, kiln). Sounds: `assets/sfx/gen_blood_kiln.py` (CC0, tonal, 4 variants each). Verified: compiles, lookups and gates in the Live Tester (`rpg_sfx_blood_kiln`); not yet in a real fight.
- **Acid and Poison upgrade sound cues (provisional sounds).** Same pattern as the Fire/Lightning cues (affected enemy, within 700 units, own 20-tic gate per element, no ticking): Acid Spray splash (`acid/spray`), Embrittlement instakill (`acid/embrittle`), Hallucinogens turn an enemy friendly (`poison/hallucinate`), Putrefaction burst (`poison/putrefy`). Switches `bonsai_sfx_acid` / `bonsai_sfx_poison` (Full tier). Weakness has no cue (it fires on every hit). Sounds: `assets/sfx/gen_acid_poison.py` (CC0, 4 variants each; Hallucinogens plays a little quieter). Verified: compiles, lookups and gate logic in the Live Tester (`rpg_sfx_acid_poison`); not yet in a real fight.
- **Fire and Lightning upgrade sound cues (provisional sounds).** Quiet one-shots at discrete events, played from the affected enemy and only within 700 units: Burning Terror frightens an enemy (`fire/terror`), Conflagration spreads to a new enemy (`fire/spread`), Thunderbolt stuns (`lightning/thunder`), Chain Lightning starts (`lightning/chain`), Revivification raises an ally (`lightning/revive`). One gate per element (20 tics, two ints on the player's stats, `TFLV_Upgrade_Dot.ElementCue`), no ticking, no loops, Full tier by default; new switches `bonsai_sfx_fire` / `bonsai_sfx_lightning` in the Sound Effects menu. Sounds: `assets/sfx/gen_fire_lightning.py` (CC0, 3-4 variants each; Hallucinogens plays a little quieter). Verified: compiles in the full load order, lookups and gate logic in the Live Tester (`rpg_sfx_fire_lightning`); not yet verified in a real fight.
### Fixed
- **Experimental: damage-over-time chains cannot nest more than 12 deep.** The game crashed (a native stack overflow, `uzdoom.exe` access violation in `ntdll.dll`, no script error) a few seconds to minutes after loading one save, in fights with Fire, Poison and Hallucinogens on many enemies. The cause is not confirmed; the chain of dot -> spread -> new dot -> damage is the leading suspect. `TFLV_Upgrade_Dot.GiveStacks` and the dot's damage call now count their nesting (`TFLV_EventHandler.chainDepth`, reset every tic); past 12 levels the application is skipped and `TFLV: damage-over-time chain stopped at depth 12` is logged (at most 5 times). If the crash goes away and that line never appears, the cause was elsewhere; if the line appears, it names the actor class. Also: Acid, Lightning, Fire spread and Elemental Synthesis no longer dereference a dot that could not be given.
- **ECM no longer scans every actor in the level each tic.** `TFLV_Upgrade_ECM.Tick` built a `ThinkerIterator` over all actors every tic while the upgrade was held. It is now event-driven: `WorldThingSpawned` hands each missile not fired by a player to the player upgrades (`OnHostileMissileSpawned`, new `BaseUpgrade`/`UpgradeBag`/`PerPlayerStats` hook), ECM keeps them in a short `pending` list, and `Tick` only checks that list (tracer is read lazily because A_SkelMissile assigns it just after the spawn; entries leave when decided, dead, or aimed at someone else; an empty list costs one `Size()` check). A missile that is not a seeker yet is kept for 5 tics so an actor that sets `+SEEKERMISSILE` from its first state is still caught. If `Tick` finds a gap (ECM toggled off, player frozen, map change, old save) it rebuilds the list with one full scan, which also picks up seekers already in flight. Ranges, chances and the three outcomes are unchanged; each outcome now lives in one place (`Redirect`, `Reprogram`, `Fail` in `ECM.zsc`) and has a tally shown by the debug dump (`BONSAI ecm ...`). Not covered: a projectile that gains `+SEEKERMISSILE` more than 5 tics after spawning. How to revert to the original scan: `docs/ECM_event_driven.md`. Verified in the Live Tester (`rpg_ecm_redirect`, `rpg_ecm_hack`, `rpg_ecm_late_seeker`).
- **Weapon-switch XP exploit: XP now goes to the weapon that caused the damage.** A burn/poison/acid/shock DoT keeps ticking after you switch weapons, and its score (Doom Points score-to-XP) or damage XP used to be paid to whichever weapon was in hand, so a big hit with a rocket launcher could level the fist. `TFLV_Upgrade_Dot` now remembers the weapon that applied it (`srcWeapon`, set on every application, copied by Elemental Synthesis and passed to the Conflagration/Chain Lightning/Acid Spray/Putrefaction spread actors via the new `TFLV_Upgrade_AuxActor`). Score points added by a damage or kill event (including the kill/timer bonus) are measured around the scoring call in `WorldThingDamaged`/`WorldThingDied` and credited to that weapon; other score (pickups, secrets, achievements) still goes to the current weapon. Event-driven only, no per-tic work. Not covered: explosions of projectiles that land after a switch still credit the current weapon. Verified in the Live Tester (`rpg_xp_credit`, `rpg_xp_credit_score`): old behaviour gave the fist 684 of ~1100 XP, now the pistol gets it all and the fist stays at 0.
- **FPS drain from `dp_MapScoreItem` tokens piling up (11,000+ on one map).** Doom Points dropped a permanent score token under every power-up giver that spawned, and Champions creates and removes `champion_AggroGiver` actors dozens of times per second, so every one left a token behind. A token now remembers its item and removes itself (after a 1 s grace period so a pickup still scores) once that item is gone. Verified: 40 transient givers left 41 tokens before the fix and 1 after; picking up a real item still scores, and the token of an item still on the floor stays. Tokens already stored in older saves have no item to track, so on every map load each one is now linked to the pickup lying under it or removed if there is none (5,005 test tokens became 22 kept). Measured in the tester on the full stack: 11,000 leftover tokens raised average frame time from 2.05 ms to 11.15 ms.
- **Companions never appeared when Colorful Hell replaced them with an RNG spawner** (only the teleport fog showed). The map-start spawn gave `TFCO_FriendEnhancer` to the spawner, whose `AttachToOwner` forces a `See` state a spawner does not have, so it was removed before creating the monster. The enhancer is now given to real monsters only; `TFCO_FriendApplicator` already gives it to the spawned monster.
- **Grappling hook stopped dead against companions** (visible hook, no pull, no stun). `HookProjectile` now ignores friendly actors and players (`CanCollideWith`).
- **VM abort on player death** (`TFLV_WeaponInfo.IsMelee`, read from address zero): the XP death penalty visits every weapon entry, including orphaned ones with a null `wpn`. `IsMelee()` and `IsWimpy()` are now null-safe, so the penalty also applies to those entries.
- **The mod failed to load without Colorful Hell** (`Unknown class name 'WhitePE2'`): `ClearFountainsOf` resolves its class names at runtime through String variables instead of string literals.
- **Hyper V reset the player's MaxHealth** every update when `vmm_max_health` was 0, undoing other mods' bonuses (e.g. La Tailor Girl burgers). It now only touches MaxHealth while the setting is active.
- **Friendly Master Sentinels no longer heal enemies through their fountains.** A companion Sentinel's `HealthFountainWhitePE` heals every monster in range, so enemies were healed and revived in endless fights. Map-start companions now get `TFCO_FriendEnhancer`, and when a Sentinel turns friendly it destroys the fountains it already spawned (matched by spawner, not proximity). The Colorful Hell fork gate (`claude/sentinel-fountain-gate`, commit `9625c3e`) stops friendly Sentinels from starting fountains, and needs that fork to be loaded. No per-tick cost; hostile Sentinels are unchanged.
  - Test-only hook `companions_test_class` (`Companions.zsc`, roster selection): spawns a named class as the first ally. Default empty, so normal gameplay is unaffected. Added for the Doom Live Tester; remove it before any release.
- **Dash stops responding mid-game until you save and reload.** Dash spends the stamina pool (`melee_stamina_val`), but the per-tic stamina recovery lived inside `V_Moves.Perform_Melee()`, which returns immediately when melee is disabled (`vmm_melee` Off, or Combat Training not yet unlocked with its Gun Bonsai gate on). With melee off the pool never refilled, so after about three dashes (30 each from 100) dash was dead; loading a save re-ran `initEvent`, which resets the pool to 100. Moved the recovery into `V_Moves.DoEffect()` so it runs every tic regardless of melee. Verified in UZDoom 5.0.3: with melee disabled, stamina went 10 to 100 in 100 tics after the fix and stayed at 10 before it.
- **Hyper-V Gun Bonsai gate redesigned: your Hyper-V toggles take precedence, upgrades unlock on top.** With a `hyperv_gb_*` option ON, a feature now runs only if (a) its own Hyper-V toggle is ON **and** (b) the matching upgrade level is reached (dash L1, double dash/ledge climb L2, double jump L3, melee/combo/parry L1/L2/L3, health/armor/ammo regen L1, hook/pull+stun L1/L2, teleporter L1, Bullet Time L1, its berserk/invuln bonuses L2). Turning double jump off in the Hyper-V menu means no Mobility level will ever grant it. Previously `TFLV_HyperV_IntegrationHandler` *overwrote* those toggles (`vmm_dash`, `sm_enabled`, ...) with the upgrade state, so the menu never showed your real choice, and nothing ran when enforcement missed (e.g. `PlayerEntered` not firing on first launch), leaving every feature available with zero upgrades.
  - The gate is now read-only and applied where features are consumed: new `vmm_GbGate` (`vmm_settings.txt`) is checked inside the `vmm_Settings` accessors and in `slomo_handler.txt`. Toggles are never written by the gate.
  - Upgrade levels are cached in new `hyperv_gb_lvl_*` CVars (`CVARINFO.txt`), written only on events: upgrade level-up / weapon switch (`OnActivate`/`OnDeactivate`), map load, (re)spawn. There is **no per-tick polling**; the idle cost is one `Size()` check per tic. Weapon-bound upgrades (Bullet Time, Hook, Teleporter) follow the wielded weapon.
  - MENUDEF notes reworded: the toggles now "set what is allowed; Gun Bonsai upgrades unlock them". Numeric scaling (cooldowns, regen amounts, speed/jump multipliers) is still driven by upgrade level.
  - **Migration:** earlier builds wrote upgrade state into your toggles, so a saved config can have dash/melee/slomo/etc. stuck Off. Re-enable the ones you want once in the Hyper-V menu. `vmm_double_dash`, `vmm_double_jump`, `vmm_ledge_climb` and the three regens default to Off.
  - Not changed: `vmm_ammo_regen_backpack` is still derived from Resupply level (existing behavior).
- **Hyper-V Upgrades balance menu — sliders now actually bind to the CVars the gameplay code reads.** `GunBonsaiStatHyperV` in `MENUDEF.txt` referenced `_lv1/_lv2/_lv3`-suffixed CVars (e.g. `bonsai_hyperv_slomo_pts_lv1`, `bonsai_hyperv_hregen_tick_lv1/lv2/lv3`, `bonsai_hyperv_tp_range_lv1/lv2`) that were never declared in `CVARINFO.txt`; the real integration code in `HyperV_GunBonsai.zsc` reads the `_base` + `_per_level` pair (per the project rule in `CLAUDE.md`). UZDoom 4.14.3 silently created phantom user CVars for the orphan names, letting sliders appear to work while doing nothing; UZDoom 5.0.3 no longer accepts input on them, which is what surfaced the bug. Collapsed each Lv1/Lv2/Lv3 slider group to the actual `_base` CVar and added sliders for the missing `_per_level` / `_min` knobs (armor-regen tick-per-level/min-tick, teleporter range-per-level/cooldown-per-level/cooldown-min). `resetcvar` reset command updated to match.
- **Profiles no longer print "float CVar not found" errors.** `Profiles.zsc` listed 15 phantom `_lv1/_lv2/_lv3` cvar names (the follow-up noted above). The `_lv1` entries now name the real `_base` cvars (hregen/aregen/ammoregen tick, tp_cd, aregen_cap, slomo_pts, tp_range) and the `_lv2/_lv3` entries were dropped together with their values in the name lists and all five profile arrays. Saved profile strings are matched by name, so old saves still load. Verified in the Live Tester (`rpg_profile_death`).
- **Doom Points scoring never built on a map loaded at tic 0.** `TFLV_EventHandler.RefreshMasterSwitches` skipped the refresh when `last_cache_tic == gametic` and the initial value was 0, so at gametic 0 every cached switch (Bonsai, Indestructible, Doom Points, Companions) read false. A `cache_valid` flag now forces the first call to refresh; per-tic caching is unchanged. Verified: `rpg_xp_credit_score` without its `load_map` step now earns score XP.

### Added
